terraform-gcp-spanner

Globally-Distributed Database Infrastructure

Google Cloud Platform Terraform Module

Executive Summary

This Terraform module provisions Google Cloud Spanner instances and databases with enterprise features. It supports regional and multi-region configurations, autoscaling with CPU and storage utilization targets, CMEK encryption for databases and backups, DDL schema management, PostgreSQL dialect, backup schedules with cron expressions, point-in-time recovery via version retention, drop and deletion protection, and IAM bindings at both instance and database levels with conditional access.

Component Breakdown

Instances (google_spanner_instance)

Created with regional or multi-region config strings. Capacity via fixed processing_units or num_nodes (mutually exclusive, validated), or autoscaling with min/max processing units/nodes and CPU/storage utilization targets. Force destroy for dev/test.

Databases (google_spanner_database)

DDL statements for schema management. CMEK encryption via KMS key name. Version retention period for PITR. PostgreSQL dialect support. Deletion protection and drop protection flags.

Backup Schedules (google_spanner_backup_schedule)

Cron-based scheduling with configurable retention duration. Optional encrypted backups with encryption type and KMS key. Depends on database creation.

IAM Bindings

Instance-level (google_spanner_instance_iam_member) and database-level (google_spanner_database_iam_member) bindings. Both support multiple members per binding and optional conditional access via CEL expressions.

Industry Adaptation

Financial Services

Multi-region instances for zero-RPO disaster recovery. CMEK encryption. Strong consistency for transaction integrity.

Gaming

Autoscaling for burst traffic. Low-latency reads via regional configs. PostgreSQL dialect for migration ease.

Retail / E-Commerce

Global distribution for multi-region availability. Automated backups with long retention. Drop protection for safety.

SaaS

Multi-tenant database design with DDL management. Database-level IAM for tenant isolation. PITR for data recovery.

Production Readiness Checklist

  • Enable CMEK encryption for databases and backups
  • Enable deletion protection and drop protection
  • Configure autoscaling with appropriate CPU/storage targets
  • Set up backup schedules with adequate retention
  • Configure version retention for point-in-time recovery
  • Apply least-privilege IAM at database level
  • Use multi-region config for disaster recovery
  • Manage DDL through Terraform for schema versioning
  • Validate capacity mode (nodes vs processing_units)

# Connect to Spanner

  --instance=YOUR_INSTANCE \
  --sql="SELECT 1" \
  --project=YOUR_PROJECT_ID
